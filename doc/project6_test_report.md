## 1. 서론

### 1.1 문서 목적 및 범위

본 문서의 목적은 조직 내 파일 관리 및 협업을 위한 웹 기반 클라우드 시스템 **Mini Drive** 프로젝트에 대한 테스트를 설계하고 그 결과를 기록하는 데에 있다. 본 문서에서는 위 프로젝트의 테스트 기준, 테스트 범위, 테스트 케이스와 테스트 결과를 명시한다.

### 1.2 프로젝트 개요

회원가입/로그인 기반의 사용자 인증, 파일 업로드·다운로드·삭제, 폴더의 계층적 관리, 사용자 간 파일 공유 및 외부 공유 링크 발급, 파일 검색, 버전 관리, 휴지통을 통한 삭제 파일 복구, 관리자의 사용자 권한·로그 관리 기능 등으로 구성된 웹 기반 클라우드 파일 관리 시스템을 구축한다. 사용자는 별도의 설치 없이 웹 브라우저를 통해 시스템에 접근한다.

### 1.3 용어 정의

| 용어 | 설명 |
|---|---|
| 클라우드 스토리지 | 인터넷 기반 파일 저장 시스템 |
| 버전 관리 | 파일 변경 이력을 저장하고 이전 상태로 복원하는 기능 |
| 권한 관리 | 사용자별 파일 접근 권한(읽기/수정/댓글)을 설정하는 기능 |
| 외부 공유 링크 | 시스템 계정 없이도 파일에 접근할 수 있도록 생성하는 URL |
| 휴지통 | 삭제된 파일을 일정 기간 동안 임시 보관하는 영역 |
| 액터(Actor) | 시스템과 상호작용하는 외부 개체(사람 또는 외부 시스템) |

### 1.4 참조 문서

1) `project1_definition.md` - Mini Drive 시스템 정의서
2) `project2_quality_attributes.md` - Mini Drive 품질 요소 정의서

## 2. 테스트 개요

### 2.1 테스트 범위

테스트는 시스템 내부 구조를 알지 못한다는 가정 하에 **블랙박스 테스트**로 수행한다. 테스트의 범위는 아래와 같다.

| 범위 | 내용 |
|---|---|
| Web 기반 시스템 | Ⅰ. 브라우저/서버사이드 동작 정확성 확인<br>Ⅱ. 요구사항(FR-001~029) 충족 확인 |
| Database | Ⅰ. 사용자/파일/폴더/공유/버전/로그 데이터 입출력 확인<br>Ⅱ. 데이터 정합성 확인 |
| 비기능 영역 | Ⅰ. 성능, 보안, 동시 접속, 사용성, 유지보수성(NFR-001~008) 충족 확인 |

### 2.2 테스트 항목 및 통과 기준

**기능별 테스트 항목**

| 테스트 항목 | 통과 기준 |
|---|---|
| 회원가입 기능 | 이름/이메일/비밀번호가 모두 유효한 경우에만 가입에 성공한다. |
| 로그인 기능 | 등록된 이메일과 일치하는 비밀번호일 때만 로그인에 성공한다. |
| 파일 업로드·다운로드 기능 | 지원 형식·용량 이내의 파일만 업로드되며, 권한이 있는 사용자만 다운로드할 수 있다. |
| 파일 삭제·휴지통 복구 기능 | 권한이 있는 파일만 삭제(휴지통 이동)되며, 보관 기간 내에만 복구할 수 있다. |
| 폴더 관리 기능 | 동일 계층 내 중복되지 않는 이름으로만 생성/변경되며, 계층 구조가 유지된다. |
| 파일 공유 기능 | 등록된 사용자에게만 공유되며, 설정한 권한(읽기/수정/댓글)대로 동작한다. |
| 공유 링크 기능 | 만료 시간이 설정된 링크만 생성되며, 만료/비활성 링크는 접근이 차단된다. |
| 검색 기능 | 조건에 맞는 파일만 3초 이내에 반환되며, 결과가 없을 때 안내 메시지를 출력한다. |
| 버전 관리 기능 | 변경 이력이 누락 없이 저장되며, 선택한 버전으로 정확히 복원된다. |
| 권한·로그 관리 기능 | 관리자만 권한을 변경할 수 있으며, 조건에 맞는 로그만 조회된다. |

**비기능별 테스트 항목**

| 테스트 항목 | 통과 기준 |
|---|---|
| 브라우저 호환성 테스트 | 주요 브라우저(Chrome/Edge/Safari 등)에서 시스템이 동일하게 동작한다. |
| 성능 테스트 | 100MB 이하 파일 업/다운로드가 10초 이내, 검색이 3초 이내에 처리된다. |
| 부하(동시 접속) 테스트 | 약 200명 동시 접속 시에도 주요 기능이 정상 동작한다. |
| 보안 테스트 | 비밀번호는 암호화되어 저장되고, 권한 없는 사용자는 파일/기능에 접근할 수 없다. |
| 사용성 테스트 | 주요 기능이 3단계 이내의 화면 이동으로 수행 가능하다. |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정

테스트 케이스는 `project5_req_analysis.md`의 유스케이스(U_01~U_14) 정상 흐름 및 대안/예외 흐름을 기준으로 선정하였으며, 블랙박스 테스트 기법을 기반으로 시스템 내부 구현을 확인하지 않는 **사용자 시점** 테스트 케이스 선정에 중점을 둔다. 비기능 요구사항(NFR-001~008)은 요구사항 추적표의 검증 방법을 기준으로 별도 테스트 케이스를 구성한다.

### 3.2 테스트 케이스 유형

테스트 케이스 유형은 다음과 같다.
- 문자열/값 입력 테스트 케이스 (회원가입, 로그인, 폴더명 등)
- 정상 동작 확인을 위한 기능 테스트 케이스 (업로드, 다운로드, 공유 등)
- 예외/대안 흐름 확인을 위한 경계·오류 테스트 케이스 (권한 없음, 만료, 중복 등)
- 시스템 전반에 적용되는 비기능 테스트 케이스 (성능, 보안, 동시 접속 등)

## 5. 테스트 환경

### 5.1 테스트 환경 구성도

Mini Drive는 별도 설치 없이 웹 브라우저로 접근하는 시스템으로, 테스트는 아래와 같은 구성에서 수행한다.

```
                 +------------------+
                 |   SERVER (DB)    |
                 |  UserDB / FileDB |
                 |  FileVersion 등  |
                 +------------------+
                    ↑            ↑
                    │            │
            +---------------+  +------------------+
            |  WEB SYSTEM   |  |  외부 공유 링크   |
            | (Client 인증) |  | (비인증 접근)     |
            +---------------+  +------------------+
                    ↑                    ↑
                    │                    │
            +---------------+  +------------------+
            | Test Client 1 |  |  Test Client 2    |
            | (일반/관리자) |  |  (외부 사용자)     |
            +---------------+  +------------------+
```

| 구분 | 환경 |
|---|---|
| 클라이언트 | Chrome / Edge / Safari 최신 버전 |
| 서버 | Mini Drive Web Application Server |
| 데이터베이스 | UserDB, FileDB, FileVersion, ShareSetting, ShareLink, Trash, ActivityLog |
| 테스트 계정 | 일반 사용자 1, 관리자 1, 외부(비인증) 사용자 1 |
